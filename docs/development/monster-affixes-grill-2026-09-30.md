## 2. 两套词缀的边界(回答 7.7 叠加规则)

制作人定了「彻底分开」,这是合理的,因为两者的**本质不同**,不是同一概念换个范围:

| | 怪物词缀 | 规则词缀(塔) |
|---|---|---|
| 作用对象 | 某个敌人 | 整段/整层的**游戏规则**(玩家侧、结算侧、远征侧) |
| 实现方式 | 往该敌人的 `bossMechanics` 追加机制注册表里的条目 | 改远征或战斗的规则开关 |
| 模块 | `src/sim/monster-affix.ts`(新) | `src/sim/tower-rule.ts`(新,批次 3) |
| 例子 | 血怒、圣咏、亡语、猎首 | 禁药、治疗减半、残血开局、死亡对赌、无营地 |

「彻底分开」要靠两条边界规则来保证不长出接缝:

1. **规则词缀不许给敌人挂机制。** 如果一条塔词缀的内容是「敌人多一个机制」,那它就是怪物词缀,应该进怪物词缀池。因此实施计划 v2 批次 3 原表里的「增援加倍」「提前狂暴」「精英附加机制」三条**移出塔词缀池**。
2. **怪物词缀不许改规则,也不许带数值倍率。** 词缀定义里只能引用机制注册表的 kind 与参数,不能出现 `attackMult` / `hpMult` 一类字段。用断言守住。

**两者如何叠加**:塔层与怪物词缀的唯一交点是**密度**。塔可以把「本段词缀怪出现率」「词缀怪词缀条数上限」作为参数传给怪物词缀生成器,但不直接挂机制。一场遭遇里同时存在的怪物词缀**总条数设上限**(占位:3),超出不生成。这是可读性底线:玩家要能在一屏里看懂自己面对的是什么。

## 3. 怪物词缀系统规格

### 3.1 结构

```ts
// src/sim/monster-affix.ts
export interface MonsterAffixDef {
  id: string                    // 'bloodrage'
  name: string                  // '血怒' —— 专名,不叫「词条」,避免与装备 affix 混淆
  /** 这条词缀逼玩家做什么不同的事。写不出来就不进池 */
  behaviorChange: string
  /** 挂到敌人身上的机制(只能引用 mechanic-registry 已登记的 kind) */
  mechanics: BossMechanicDef[]
  /** 克制方:至少一个装备侧 + 至少一个技能/指令侧,必须能在注册表里解析到 */
  counters: { gear: string[]; skill: string[] }
  /** 名牌、进场提示、日志、死因里用的文案 */
  telegraph: { plate: string; entry: string }
  /** 允许挂的层级 */
  tiers: Array<'elite' | 'boss' | 'pack'>
}

/** 唯一入口:给一场遭遇里的敌人 roll 怪物词缀。确定性,从 run 种子派生 */
export function rollMonsterAffixes(enemies: Combatant[], ctx: AffixRollContext, rng: Rng): AppliedAffix[]
```

- 杂兵不挂(`tiers` 不含普通怪)。探讨记录「杂兵挂词缀 = 噪音」成立。
- `rollMonsterAffixes` 是**唯一**给敌人加怪物词缀的入口。M2 之后的闯入怪与宿敌回归都走它,不另写。
- 词缀 roll 在**进入路线节点时**就确定(存进 `DungeonRun` / `TowerRun`),不是开打才 roll。否则侦查无从揭示。

### 3.2 首批 4 条(批次 3)

每条对应制作人要的一种感觉。机制实现尽量复用注册表,新增部分标 ★。

| 词缀 | 感觉 | 行为改变 | 实现 | 克制(装备侧 / 技能指令侧) |
|---|---|---|---|---|
| **血怒** | 逼你提前跑路 | 血量低于阈值后攻击持续爬升。打得慢就会越来越危险,必须判断「爆发收掉」还是「现在撤」 | `enrage`,★新增 `hpBelow` 触发参数(现只有 `atTick`) | 嗜功(对精英增伤)/ 火法引爆(#1.3)、`orderRetreat` |
| **圣咏** | 逼你留着打断 | 周期读条给同伴加护盾,读完整场会越来越难打 | `cast-buff`,★新增 `target: 'ally'` 与护盾效果;可打断性由注册表 `breakDamage` 自动获得 | 磐石(减 Boss/精英伤害,拖得起)/ 招牌打断技(#1.1)、`setFocus` 集火 |
| **亡语** | 逼你控制击杀节奏 | 死亡时召唤增援或留下爆炸预警区。队伍残血时杀它会出事 | `summon` / `telegraph-aoe`,★新增 `onDeath` 触发钩子 | 饮血(击杀回血)/ 范围技、`setFocus` 改集火顺序 |
| **猎首** | 逼你换站位换人 | 周期把血量最低或治疗者拽到前排点名 | `pull`,★新增目标选择参数 `pick: 'lowestHp' \| 'healer'` | 磐石 / 坦克嘲讽类技能、出发前把脆皮换下 |

★ 共 4 处注册表扩展,全部是**给现有 kind 加参数或触发点**,不新增 kind。其中 `onDeath` 钩子是通用能力,后续词缀会复用。

### 3.3 可见性红线(不可降级)

永久死亡加上玩家有感情的角色,意味着「无预警杀人」是退游帖,不是话题。每条词缀在造成死亡之前必须经过三层可见:

1. **名牌**:敌人名字前挂词缀名,如「血怒·圣咏的沙蝎战首」。
2. **进场提示**:遭遇开始时一行日志加音效。
3. **触发提示**:触发瞬间(血怒爬升、圣咏读条、亡语预警)有独立事件与日志,和机制读条共用同一条 `casting` / telegraph 通道。

验收:任一词缀造成的阵亡,在死亡之前的日志中**必有**该词缀的进场提示与触发提示。写成断言。

### 3.4 入池标准(每条都要过)

1. **行为改变测试**:`behaviorChange` 能说清「它逼玩家做什么不同的事」。
2. **克制测试**:`counters.gear` 与 `counters.skill` 都非空,且每项都能在传承威能 / 触发词条 / 技能注册表里解析到。答不上来的不进池。断言守。
3. **认知即决策**:玩家认出这条词缀的那一刻,必须有一个可做的决策(绕路、撤退、换人、集火、留打断)。这是制作人原话「这个怪会血怒,是不是要提前跑路」的机器可测版本:侦查揭示后至少一个选项(绕路 / 营地换装 / 出发前换人)可用。

完整池上限 8–12 条,M2 之后再扩。

## 4. 侦查:情报分级揭示

### 4.1 分级

| 揭示级 | 玩家看到 | 来源 |
|---|---|---|
| 0 | 什么都不知道 | — |
| 1 | 「这个节点有词缀怪」 | 熟练度 `kind`(≥35) |
| 2 | 「有几条词缀」 | 熟练度 `full`(≥60);或熟练度 `kind` + 队伍里有侦查者 |
| 3 | 「具体是哪几条词缀」 | 熟练度 `full` + 队伍里有侦查者 |

复用现有 `revealLevel()`,不新建第二套迷雾。侦查者的作用是**把揭示级 +1**,上限 3。

### 4.2 批次 3 接两种来源

- **副本熟练度**:直接复用。高塔没有熟练度,塔里的词缀情报只来自侦查者和(M2 后)消耗品。这会让侦查者在塔里格外值钱,这是有意的。
- **队伍里的人**:游侠职业与特定特质带「侦查」标记。数据侧加一个布尔标记,不新增属性。带不带他,成为出发前的选人决策。这也是「塔逼最优、叙事逼感情」张力的直接来源。

M2 之后再接:**消耗品 / 花钱**(依赖批次 4 补给成本)、**事件**(需要破例解冻事件表 B6,届时单独 grill)。

## 5. 营地换装

- **备用格**:出发时从仓库选若干件装备放进全队共享的备用格(占位:3 格)。带什么备用件,本身就是出发前的押注。
- **换装时机**:只在路线上的 `rest` 节点可换;高塔每段之间视为营地。其余时候锁定。
- **存档**:`RunCore` 新增 `spares: ItemUid[]`。**这个字段要在 #0.6 里一起建**,否则批次 3 又要多一次存档迁移(与 `pendingLoot` / `affixes` 预留同理)。
- 备用格数量与「是否和补给额度挂钩」留到批次 4 补给成本落地时再定。

## 6. 装备构筑:主力配装 + 应对件

### 6.1 分工

| 层 | 负责 | 说明 |
|---|---|---|
| 品质 / tier 的数值 | 变强 | 基础战力的成长,C4 解冻后调 |
| **tier 的规则槽** | **构筑空间** | 见 6.2。高 tier 不只是数字大,而是能装更多规则件 |
| 规则件(传承威能、触发词条 #2.3、套装) | 构筑深度 | 数值冻结下的深度来源,组合而不是数字 |
| 装备绑人(磨合、遗物) | 情感 | 已有系统,冻结保留(D-1) |

### 6.2 tier 的构筑意义:规则槽

| tier | 规则槽 | 含义 |
|---|---|---|
| T1 | 0 | 纯属性,过渡装 |
| T2 | 1(传承威能**或**一条触发词条) | 开始有身份 |
| T3 | 2(传承威能 + 触发词条) | 能组合,构筑从这里真正开始 |
| T4 | 2 + 可指定其一(接 #2.6 确定性改造) | 能定向做一件应对件 |

这样「T2 横向构筑保留」(U09)与「高 tier 值得追」同时成立:好 T2 仍有用,但 T3 能做 T2 做不到的组合。具体槽数是占位,批次 2 定。

### 6.3 克制网

构筑深度来自三方互相克制:

- **怪物词缀**:敌人会做什么;
- **规则件**:装备能反制什么;
- **招牌技能**:玩家能主动打断什么。

8 种传承威能在批次 2 改造成克制件,方向如下:

| 威能 | 现状 | 改造方向 | 克制 |
|---|---|---|---|
| 嗜功 | 对精英/Boss 增伤 | 保留 | 血怒 |
| 磐石 | 减 Boss 伤害 | 扩为减精英/词缀怪伤害 | 猎首、圣咏 |
| 饮血 | 击杀回血 | 保留 | 亡语 |
| 烬衣 | 灼热减半 | 保留,后续扩为环境类 | 灼热、塔规则词缀 |
| 锋镝 | 攻击 ×1.1(纯数值) | **改为规则**:如「对读条中的目标增伤」 | 圣咏 |
| 春霖 | 受疗 +0.08(纯数值) | **改为规则**:如「被点名 / 被拽时获得护盾」 | 猎首 |
| 凯歌 / 拾荒 | 结算侧效果 | 保留,不参与克制网 | — |

改造锋镝、春霖是把纯数值换成规则,总强度对齐原值,不算 C4 意义上的调参,但须在 HANDOFF 写明。

### 给 #0.10 的即时修改(shldo 正在做)

`DeathCause` 现在就定成结构化的,不要用字符串:

```ts
export interface DeathCause {
  kind: 'battle' | 'mechanic' | 'event' | 'scar' | 'other'
  killerName?: string
  mechanic?: MechanicKind       // 死于哪个机制
  affixes?: string[]            // 预留:死于带哪些怪物词缀的敌人(批次 3 填)

}
```

现在 `run.ts:194` 写的是字符串 `陨落于${name}`。碑文文本由 `DeathCause` 渲染出来,而不是反过来。
