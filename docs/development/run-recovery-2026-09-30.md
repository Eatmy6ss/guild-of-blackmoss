# #0.6 远征保存与恢复

基准 `1e834c9`（已含 #0.10/#0.5），开发分支 `codex/run-recovery`。用户要求完成这一项后推送并开中文 PR。本轮完成现有副本/高塔的断点保存；发版状态与 PR 链接以 [HANDOFF](HANDOFF.md) 顶部为准。

## 目标与实现

刷新页面回到出征前会丢失已发生的战斗、阵亡与奖励。本轮让现有 `DungeonRun` / `TowerRun` 从出发就是 JSON 数据，以成员/地图 ID 解析运行时视图。战斗、暂停/挂机、选路、药水/冷却、保险、成长快照、掉落 UID、事件与已选结果一起保存。存档 v20→v21 逐级迁移，旧档资产、物品编号和公会 RNG 保留，无活动远征。

远征控制状态收拢为 React reducer，生命周期仍由原来的两种 Run 表达；没有第二套模拟/结算或第三个远征引擎。`settleEncounter` 在克隆的公会/Run 上推进随机序列并产出结果，App 应用资产与阶段后才保存，跳过 effect 中尚未提交资产的旧渲染。保留塔层金币立即到账和原有奖励公式，预留的 `pendingLoot` 仍为空。

恢复先停在标题页，进入旅程后显示原战斗与事件；运行中的战斗保留运行状态，暂停中的保留暂停。已播视觉事件不重播，事件结果可再阅读但不再执行报酬。活动远征不额外领取公会离线零工收益。访客身份、成员生成编号和已用名字同步保存，避免招募结果或重名避让随刷新变化。

召唤单位原先依赖模块全局编号，页面重载后可能与存下的单位撞号。编号改为每场 `BattleState.unitSeq`，初始与宠物/Boss/临终呼援走同一场序列；仅改变身份表示，不改变技能、伤害、敌人属性或机制时间。完整新旧战斗对照见下方。

坏远征断点拒绝导入和自动覆盖；主档损坏时恢复有效备份并提示。主档与备份均坏时保留原始数据、停止自动保存，玩家确认导入有效档或明确重开后才恢复写入。导入预览本身不解除保护，写入失败不假称已导入。

开发中实际发现并修正：

- 全局召唤序号刷新后撞号：改为本场游标，补“夹入其他场投影仍同结果”的探针；临终呼援用确保触发的随机输入验证真的新增一名单位。
- reducer 外的 ref 修改发生在最后一次发布之后：改为统一写入权威控制状态；保存只接受已提交的同一份状态，避免阶段已经结算而资产还是旧值。
- 待选事件恢复时弹窗挡住标题页“继续旅程”：进入游戏后再显示；标题页停止计时与挂机选择，真实 App 回调回归与页面刷新均覆盖。
- 刷新后延迟后果对象身份不同：按事件 ID/到期日只移除队列中的首个匹配项，保持原消耗规则。
- 最初王国回归失败源于历史脚本仍从 Run 读取成员引用：改为测试侧显式解析，不恢复生产共享引用。该组重跑 10/10；不把首次完整 verify 的退出 1 记为通过。
- 历史 E2E 依赖 Mac Chrome，与本机/工具访问约束不兼容：保留已有脚本，以真实 App 回调和隔离端口的真实页面验收替代本轮执行；不宣称旧 E2E 已跑。

## 验收口径与边界

“逐字节一致”比较完整数据的规范 JSON（对象键排序；数组、值、UID、日志、RNG 均保留），不比较对象插入顺序与真实保存时间 `lastSeen`。原因是可选心愿清空后重新生成会把同一字段插到对象末尾，键序本身不是玩法差异。Run 刚生成时直接 JSON 往返深相等；后续变动中允许可选字段为 undefined，由持久检查点统一成 JSON 缺省。

“无 def 对象”限定为不再持有整份副本或活成员，不要求重写整个战斗引擎的技能/敌人配置。现在的配置快照纯 JSON、无函数/循环，与数组/冷却/机制游标一起恢复。后续变更技能数据时必须考虑旧活动断点，不能把读档当成重开一场。

尚未覆盖：自然养成、全职业胜率与长期经济；页面未自然发生阵亡/团灭，相关后果由真实结算及 App 回调覆盖；没有多浏览器、浏览器被强制终止瞬间或跨版本热换技能的兼容验收。按 React 提交后的检查点保存，不承诺操作系统强杀时零毫秒数据损失。已有生产大包提示仍在。

批次 0 剩余三项代码准备完成，但不将历史难度倒挂自动标为解决，也不以本轮断点验收代替批次出口/玩法手感审查。下一步先审查本轮 PR 和出口证据，再推进 #1.1 招牌技能。
