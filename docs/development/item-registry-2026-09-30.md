## 最小实现和规格校准

- `src/state/item-registry.ts` 是登记与转移入口：注册表 `items`、下一编号 `itemSeq`、装备/仓库/遗物 UID 归属；操作返回一次完整的新归属，成功后检查 I6。外部新物品登记时生成 `it_n`，装备遗物转移保留原 UID，销毁删除记录但不回退序号。
- 正式 App 只持有一份 `GuildItems` 归属；背包和遗物列表从它解析。存档成员的装备保存 UID；模拟与既有 UI 的 `Member` 保留解析视图，视图指向注册表物品，不能作为第二份物品数据或转移入口。整理物品时只重绑装备视图，保留成员对象引用，避免远征与事件分叉。未趁机改战斗接口或 #0.6 运行对象。
- `ItemInstance` 字段、词条结构和装备内容不变；身份重签发是本项既定要求。正常 v20 导入不再次编号，新旧物品属性继续通过现有引擎计算。
- 旧 ID 相同不能证明两份内容相同：迁移逐实例保存内容，装备中 > 遗物 > 背包的首个实例保留原归属；其他同 ID 实例重新编号并回到仓库。新格式重复 UID 引用也保留一份独立副本至仓库，不静默丢数量。
- 正常孤儿物品回仓库，缺失引用移除并警告，槽位错误或亡者残留装备回仓库。不可解析的损坏物品无法恢复真实内容，会清理并警告；不凭空构造属性。运行时坏归属禁止覆盖好存档与备份，修复发生在加载/导入边界。
- 历史测试中使用旧实例格式却声称当前版本的合成档已修正；版本迁移测试使用真实旧形态。属性、经验、奖励与保险数值断言保留，不能用结构升级掩盖数值变化。

## 验证结果与修正分析

- 七项新注册表测试覆盖旧重复 ID 的各份内容、v1–v19 逐级迁移与 v20 正常往返、损坏引用/孤儿/编号修复、原子换装、真实副本/高塔阵亡及保险结算、100 次生成销毁后序号不复用、坏归属不覆盖好档/备份。新档和迁移不额外消耗 RNG，属性投影与旧实例相等。
- 四项新增玩法回归直接抽取当前 App 回调，覆盖换装/变卖/拆解的旧选择与重复动作、物品更新保留 Run 成员引用、UID 赎回资金/重复保护、进入高塔清显示但保留实物。历史 AST 隔离作用域和合成存档随接口升级；保留原数值断言，不以新期望绕过旧行为。
- 实际 `scripts/dev-save.ts` 在隔离写入目标下生成 v20：26 件登记、26 个唯一拥有者引用、itemSeq 27；旧 `docs/dev-save.txt` 保留为旧档证据，没有被测试生成器覆盖。
- 最终完整 `npm run verify` 实际退出 0：Vitest 50（11 文件）、管理员类型检查、smoke 47、玩法 73、王国委托回归、游戏类型及生产构建。显示修正后重新跑过最终完整检查；差异格式检查通过。

## 独立页面闭环

测试仅使用 `127.0.0.1:5462` 的合成 v19 公会：三名 15 级角色、9 件穿戴、5 件仓库、1 件待赎遗物（共 15 件），含一份旧重复 ID；1500 金、20 祝福、4 星髓、王国信任 150。用户原 5178 页面和真实存档未写测试数据。

1. 实际加载迁移，重复旧 ID 的内容保留在仓库；赎回 99 金、变卖 T1 得 57 金、拆解 T3 得 2 星髓，兑换 T3 花 800 金/10 祝福/2 星髓。原遗物 UID 保留，销毁的 it_14/it_11 从注册表删除；兑换新物品 it_16。
2. 测试守卫换穿兑换剑、卸下并交测试牧师，守卫重新穿原剑；仓库与装备之间各件只有一个引用，原装备内容与守卫原战力/血量恢复一致，换装没有额外治疗。
3. 真实高塔 1–3 层、投保一次 120 金、守塔者掉落戍卒锁甲（it_17）并带奖回城；各角色经验 88、士气 78、每对默契 3，手动纪录 3。最终 651 金＝1500−99+57−800−120+113，祝福 10、星髓 4；15 件＝9 穿戴+6 仓库，遗物 0、itemSeq 18，15 个引用唯一且均能解析。
4. 刷新后通过游戏导出代码核对，再用游戏导入预览/确认重新导入同档；注册表、全部装备/仓库/遗物引用、itemSeq、RNG、金币均不变。页面无 error；人为损坏的旧重复归属警告因开发 StrictMode 的两次初始化显示两条相同记录，正常 v20 刷新/导入未追加警告。最终仓库画面与导出核对证据在本机忽略目录 `.vite/item-qa`，关键结果已记录于本专题，不依赖临时文件接续。
5. 页面发现旧兑换被计入塔的“本次远征共获得”显示；`enterTower` 补清空 `lastDrops`，与副本出征一致，实物不变。对应真实 App 入口回归纳入最终 verify；未为这一行显示修正重复手动三层流程，不宣称第二轮实战验收。
