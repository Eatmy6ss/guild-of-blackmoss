## 二、装备设计问题：方向已认可，尚未实施

| ID | 问题 | 当前事实与建议边界 |
|---|---|---|
| E01 | 治疗装备定位偏差 | 春霖法杖、晨祷权杖、部分祭袍等主要增加佩戴者受疗，不是对队友的治疗输出。属性本身按其定义工作，这是定位问题，不是“受疗结算Bug”。应区分治疗输出与受疗并核对具体技能收益 |
| E02 | 词条全局等权、缺少底材倾向 | `rollAffixes` 从全部词条抽取，不能保证职业命名的装备具备相应属性。建议倾向池＋通用池，不新增职业穿戴硬锁 |
| E03 | 同属性多档词条与品质预算不够清晰 | 同属性不同名称可同时出现；紫装主要是数值倍率及有条件追加一条，并不保证用途适配。应明确阶级/品质/词条档位各自职责；“紫装必定比任何绿装好”不是目标 |
| E04 | 评分上涨不保证实战提升 | 连续养成换装配对四组均有胜转败。当前换装机器人只用面板启发式，不是游戏已有自动换装系统。角色技能、治疗、抗性和特殊效果价值需核对，界面应展示取舍 |
| E05 | 荆棘产出与隘口准备的衔接尚未证实 | 已有绿色以上T3首杀保底，但随机装备未必适配三人主力。没有证据证明必须全身T3；好T2继续有价值。先查用途/部位覆盖，再决定是否需要防重复或定向保底 |

用户认可的修改方向：职业属性纠偏→词条倾向→品质规则→掉落适配→比较界面。具体预算、概率、保底次数及旧装备兼容尚未确定/实施；本次盘点没有顺带新增洗练、货币、套装或锻造系统。

## 五、验收与协作缺口

- **完整真人式新档流程未完成**：目前是定向浏览器流程＋确定性探针，仍缺少包含事件/委托/建筑/随机种族/轮换的自然跨图验收。
- **隘口Boss浏览器验收未完成**：明确增援和错峰已经引擎回归，浏览器实际见到唱诗打断/吐息，但后续一死撤退，没有亲手通关或看到Boss增援。
- **移动端与长时间运行覆盖有限**：只做过部分窄屏基地等检查，不能等同战斗/所有面板全覆盖；长期高塔、事件频率/收益仍待验证。
- **共享引擎修复有全局影响**：龙鳞/重甲、挂机读条识别等并非只影响隘口；当前自动回归通过，仍需多职业、多混合专精和真实装备验证。
- **文档状态混杂**：SYSTEM-MAP为旧基准快照；BACKLOG/HANDOFF内有历史状态、旧数值和旧“下一步”，不能直接据此把已修复问题重新排期。以HANDOFF最新阶段及本盘点为接续入口，历史专题保留其证据范围。
- **交付尚未完成**：本分支有大量本地未提交修改和新文件，尚未推送、合并或部署，也未完成这一批的ZCode最终独立复审。本盘点未查询远端发布状态，不把历史PR记录当作线上状态证明。
