# K01 王国委托：本轮范围与验收

用户授权：新增王国任务，设计数值、奖励、背景关系和任务联系，并验证、打磨到本轮完成；每轮开发维护HANDOFF。

实现方案：灰冠王国的边境委托线，10份一次性委托，最多同时接取2份；从商路巡防与训练整备开始，连接现有Boss、副本与建筑。接受后才统计战斗/通关；建筑目标认可已有建设。撤退保留已完成胜场，失败不增加进度。领取只能回到公会后执行，每份只领一次。可以撤销未交付委托，重接从零累计战斗进度，无扣信任或隐藏时限。

每份委托具有委托人、来函、前置、目的地、明确目标、固定信任与酬金/补给二选一、结案回信。里程碑给予固定属性装备，避免奖励预览与到账随机不一致。领取后增加王国信任，20/50/100信任分别获得3%/6%/10%药水采购优惠（向上取整价格），不直接放大所有战斗数值。

数值基准：原游戏普通胜场30金、Boss80金、通关100金。王国奖励为一次性的额外成长资源；前期巡防80金基础额度、训练整备60，后期200—300。补给方案减少40金换治疗药2与祝福1；酬金方案按基础金额加爆发药1。信任不因方案改变，避免把选择伪装成隐藏善恶惩罚。

不扩展：多人联机、离线任务、随机日常无限刷奖、独立王国地图、全局经济重做。既有审查问题仅在直接影响本功能时修正。

验收：新档可见入口；前置任务正确锁定/解锁；两份上限；只有接取后对应胜利计数；错误副本/失败/高塔不计；建筑即时更新；领取二选一且不能双领；奖励和回信、信任、折扣可见；旧v11及更旧档迁移默认无委托；v12导入导出保留状态；重开清空委托；桌面与窄屏可用；构建与定向回归通过。

## 实现与存档边界

- 数据在 `src/data/kingdom.ts`；接取/推进/领取/折扣在 `src/sim/kingdom.ts`；界面在 `src/ui/KingdomPanel.tsx`。
- `settleKingdomBattle` 在 `advanceRun` 之前读取当前遭遇，并要求 battle阶段 + guild-win；其他副本、高塔、失败、主动撤退均不伪造进度。已取得胜利的累计值不被撤退清除。
- 战斗仍沿用原游戏“远征结束才落盘”的策略；途中强制刷新会回到出征前，规则文案已写明。没有单独保存任务进度来制造资产与战绩分离。
- 领取先同步登记receipt，再由React同一事件批量更新金币、祝福、药水、装备与编年史；持久化为同一存档快照。用固定 `royal-委托ID` 物品ID避开随机掉落编号。
- v11→v12补空王国状态；加载时修复缺失/重复/未知任务记录并限制进度。信任从已结案任务推导，不保存第二份可漂移数值。
- `SaveTransferPanel` 替代旧存档prompt弹窗：导出可复制文本，导入先校验与预览、再明确替换。剪贴板不可用时选中文本供手动复制。
- 重开函数接入了清空kingdom；原重开公会的浏览器confirm和不完整重置是历史问题，本轮未做完整重开UI验收，另列F13。
