# T01 管理员战斗实验室

2026-09-27，实现并验证；已随 `076aaf4` 推送至 `codex/mechanic-registry`，已创建 [PR #3](https://github.com/Eatmy6ss/guild-of-blackmoss/pull/3)，待有写入权限的协作者批准后合并。用户要求自由选关、配队、调整等级装备以反复测试技能，并明确“管理员测试模式，不要和正式游戏耦合”。

## 使用方法

在当前开发工作树运行 `npm run dev:admin`，打开 `http://127.0.0.1:5180/`。这是独立本机入口，无需注册游戏账号；服务器默认仅监听本机，端口被占用会报错，不自动切换到其他端口。

1. 选择副本和具体遭遇，展开各试员配置职业、专精、等级、精进技能与装备。
2. 按需禁用技能、调整冷却或改变种子，点击“应用配置并备战”。初始处于暂停状态。
3. 开始播放、暂停、单步 0.1 秒、推进 1 秒，或快速计算至终局。支持 1/2/5 倍播放、阵型、集火、药水及自动指挥。
4. 看实际生命、技能冷却、单位伤害/治疗记录与战斗日志；“生成测试报告”提供可复制的配置和结果。
5. “同条件重战”使用上一场已应用的配置，恢复生命、药水和冷却；“应用配置并备战”使用当前表单。表单更改尚未应用时有提示。

支持 12 座副本的全部现有遭遇，1–6 人队伍，六职业、现有基础和混合专精、6 级起的精进技能，1–15 级、全部装备基底和三种品质。装备预设仅显示数据表实际存在的 T1–T3。

## 隔离边界

- 工具代码位于 `tools/admin/`，独立 HTML、React 根节点、Vite 配置和 `dist-admin/` 输出。正式 App、菜单、路由和默认生产构建没有接入它。
- 工具单向调用现有数据表、战斗引擎和 Pixi 渲染器，以验证当前游戏实现；正式运行入口不依赖管理员工具。没有复制一份可能漂移的战斗逻辑。
- 配置仅访问 `blackmoss-test-lab-v1`，且本机 5180 与正式游戏不同来源。没有读写 `guild-game-save-v1`、导入正常公会、调用远征奖励/结算/存档接口。
- 技能覆盖发生在克隆后的测试战中，每个队员分别复制技能定义。同职业队员也能有不同冷却；不会修改 JOBS、其他队员或下一场默认配置。
- 战斗死亡、消耗、胜利都留在内存；不发奖励、不推进委托、战绩或成长。刷新仅恢复测试配置，不恢复进行中的战斗。
- 这是本机管理员工具，未实现或接入线上账号/管理员权限系统，也未部署。

## 测试口径与边界

- 默认提供守卫/牧师/游侠三人队、Lv10 精良 T2，烬石隘口首领。它是可改的样本，不代表推荐通关配装。
- 人物采用固定人类样本，装备词条固定抽样。改变种子只改变战斗随机。固定配置且指挥操作相同时可复现；“同条件重战”不回放上次的手动操作时序。
- 当前单场测试没有公会建筑、纪念光环、手册、远征事件加成和自然成长过程，也不包含高塔楼层生成。因此不能将结果直接当作正式全流程胜率或经济结论。
- 冷却调参只覆盖当前技能的冷却时间；没有开放改技能伤害、公式或全局数据表。引擎仍在单位可行动时检查技能，不保证冷却归零立即施放。
- “命中伤害”按引擎伤害事件累计，含过量伤害，反击不并入；治疗也按事件量累计。不是逐技能 DPS 或有效治疗统计。页面展示最近 120 条日志，报告保留引擎当前日志（最多 400 条）与事件。
- 报告是当前结果快照，复制留存；本轮没有报告导入、多个配置槽或跨机器同步。窄屏战场可横向滚动，下方另有敌人集火按钮。

## 验证证据

- `npm run verify` 退出 0：Vitest 8 项（7 项管理员测试 + 1 项真实战斗集成）、管理员类型检查、smoke 47、历史玩法与王国回归、游戏类型检查和生产构建通过。
- 管理员测试覆盖：专用存储键、损坏配置回退、边界规范化、全部副本遭遇/专精创建、冷却和禁用隔离、全部装备品质生成、重复战斗一致且不回写配置/成员。
- 浏览器实际验证：鳞音首领 + 威吓冷却 2 秒，单步后真实剩余冷却 2 秒；连续两场均 83.1 秒胜利，结果和日志一致。刷新保留关卡与冷却，战场回到等待备战。
- 已验证等级 12、史诗 T3 换装、禁用/还原技能、增减队员、实时推进/暂停、用药/分散/自动指挥，以及重战重置。最终恢复默认三人配置，烬石隘口首领暂停备战。
- 本机窄面板未出现整页横向溢出，战场局部滚动；浏览器错误/警告记录为空。没有做多浏览器或手机真机兼容验收。
- 独立管理员构建成功；正式 `dist/` 不含管理员标识/配置键，`dist-admin/` 不含正式存档键。构建仍有既有体积提示，未扩大本轮范围拆包。
- 与 #0.7a 开工前快照逐一核对 78 个既有源码/脚本文件，哈希全部一致：本轮技术准备与管理员工具没有追加修改正式玩法。Git 差异中的 #0.1 源码修改属于前一轮，继续保留。
