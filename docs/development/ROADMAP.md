### 3.3 事实账本(A2)

**为什么需要**:说书人要讲「遗物又等来了下一位主人」「他终于去了那个地方」,前提是能查到「这件遗物以前属于谁」「他以前在那里经历过什么」。现在这些信息都查不到:

- 装备实例没有来历字段;
- 遗物只记英雄名;
- 延迟后果只有 `{eventId, dueDay}`。

**结构草案**(字段名可以调整,约束不可以调整):

```ts
// src/sim/fact-ledger.ts
export interface Fact {
  id: number                       // 单调序号,和 itemSeq 一样防复用
  day: number
  kind: 'death' | 'scar' | 'relic-bind' | 'relic-redeem' | 'item-inherit'
      | 'wish-done' | 'event-choice' | 'consequence-due' | 'first-kill'
      | 'bond-star' | 'tower-record'
  actors: string[]                 // memberId
  refs: { itemUid?: number; eventId?: string; bossId?: string; dungeonId?: string; floor?: number }
  cause?: DeathCause               // kind = death 时必填
  links?: number[]                 // 本事实由哪些旧事实引起(consequence-due → event-choice)
}
```

约束:

1. **唯一写入口**:`settleEncounter` 的 consequences、事件结算、遗物赎回和传承。`App.tsx` 不直接写账本。
2. **账本只追加**。编年史继续存成品句子,不迁移旧条目;账本只记录从 v22 开始的事实。
3. **存档从 v21 迁移到 v22**,旧档的账本为空。
4. 断言(写关系,不写数值):
   - 每个 `death` 事实都有 `cause`;
   - `consequence-due` 事实的 `links` 指向一个已存在的 `event-choice`;
   - 同一个 `itemUid` 在同一时刻只有一个 `relic-bind` 处于有效状态。
5. 体积控制:需要上限策略,例如只保留最近 N 天的全部事实,再加上永久保留的死亡和遗物类事实。N 是结构占位。

### 3.4 说书人 A 步(A9)

按 U23 定的规则执行:

- **时机**:每趟远征回城结算后,**最多讲 1 条**,挑本趟最强的一次碰撞。本趟没有值得讲的就不讲。
- **范围**:只讲**本趟结算内**的碰撞,以及**延迟后果兑现**这一种跨时间情形(因为 `links` 能证明因果)。
  - 例:首杀加上当场阵亡,讲成「用命换来的首杀」;
  - 例:濒死创伤加上同趟后续战斗的表现;
  - 例:事件的第二幕兑现。
- **文本规则(U23 融合原则)**:
  - 前面是**事实句**,只写账本里有的细节:人名、地点、机制、词缀、第几次。
  - 最后可以接**一句收尾解读**,用来营造气氛。
  - 收尾句必须挂在一条账本事实上。没有对应事实的解读不许出现。
  - 正例:「他没有再去过那片沼泽。」这句对应账本里的「此后无该副本出征记录」。
  - 反例:「那一夜之后他变了。」前提是账本里没有创伤或性格变化的记录。
- **文本来源**:人工手写模板加槽位,禁止程序拼句。首批约 5 类碰撞,每类 6 条,约 30 条,按事件文本的规范过三审。模板放在 `src/data/story-templates.ts`。
- **入口唯一**:`src/sim/storyteller.ts` 里的 `tellExpedition(ledgerSlice, rng): StoryEntry | null`。只消费账本,不读 `App.tsx` 的状态。
- **跨时间缝合**(遗物传承、心愿与旧事件、宿敌)放到阶段 B,等账本积累了数据再做。

### 3.5 美术改版的对接

**现状**:

- 美术同伴正在改风格,但 HANDOFF 里没有登记,制作人也不清楚具体范围。
- AGENTS.md 的红线规定:美术和 UI 换皮必须先问制作人。

**U24 定调**:没有原创美术能力,走「**免费素材 + agent 改造**」。这类路线最大的风险是**拼贴感**——不同来源的素材放在一起显得廉价。对策是:**视觉身份不靠原画,靠统一色板 + UI 框体 + 字体 + 编年史版式**;所有精灵(含 agent 改过的)一律压到同一套有限色板。

需要补上以下几步:

1. **美术同伴在 HANDOFF 顶部登记认领**,写明四件事:范围(精灵、地块、UI、字体中的哪些)、分支名、风格参考图、预计交付节奏。
2. **制作人先审方向,再做合入。** 可以先交一屏 mockup 或 3 张样张,方向确认后再批量替换。
3. **代码准备工单(A12,1.5 人日)**,目的是降低换美术的成本:
   - **精灵按 id 绑定,不按名字绑定。** 现在 boss 精灵是在 `pixelSprites.ts:656` 附近按中文名子串匹配的,例如 `n.includes('格鲁什')`,敌人改个名就会掉图。改为在数据表里给敌人和 boss 加 `sprite` 字段,匹配逻辑只作为缺省兜底。再加一条断言:每个 boss 都有显式的 sprite。
   - **颜色收进主题变量。** CSS 里有 134 处硬编码色值;Pixi 里的 62 处 `0x` 色值集中在 `COL` 常量里,把它们挪到一个主题模块,方便美术整体换色板。
   - **锁定色板。** 选一套有限色板(如 32 色以内),写成脚本:任何新素材入库前自动量化到该色板。这一步是整套路线成立的前提。
   - **逐文件许可清单**(`public/assets/CREDITS.json` 或同类):每个文件记来源 URL、作者、许可证、是否被 agent 改过。现 README 只笼统写「DCSS CC0」,hierophant 等较新怪物图是否在 CC0 包内**需要核实**。只收 CC0 / CC-BY(署名入致谢界面),**不收 CC-BY-NC、「免费但无许可证」和来源不明的素材**。
   - **致谢界面**:标题页加入口,读许可清单渲染。
4. **美术不阻塞 G2。** G2 用当时已经合入的美术。如果改版到一半,就用旧美术去试。G2 测的是玩法,不是卖相。

**2026-10-01 技术实现校准（shldo，非整项验收）**：用户已正式授权原素材主题的免费资源迭代，范围/证据见HANDOFF顶部、DECISIONS R05及[资源库首轮](art-resource-library-2026-10-01.md)。稳定ID绑定采用显示层表，不给模拟数值/存档增加sprite字段；色板在共享纹理准入时自动映射，原PNG完整保留用于来源追溯。两项实现满足改名不掉图与共同色板的目标；旧CSS/Pixi色值全面收口、独有动作与人工视觉验收尚欠，不把A12/A17或G2标成全部完成。

## 4. G2 · 首轮外部试玩

### 4.1 规格

- **人数**:5–10 人。来源是朋友熟人和社区(Discord、贴吧、小黑盒等),**其中至少 3 人是陌生人**。朋友的反馈往往偏客气,所以分析时把两组分开看。
- **方式**:试玩者自己玩,不讲解。至少 3 人全程录屏,或者由制作人在场观察但不说话。
- **时长**:建议首局 45–60 分钟,之后是否继续由试玩者自己决定。**「自己决定继续」这件事本身就是最重要的信号。**

### 4.2 问卷(6 题)

1. 你会在明天再打开它吗?(是 / 可能 / 否)
2. 你用过哪个招牌技能?在什么时候用的?为什么那时候用?
3. 有没有哪一刻让你觉得「这是我的决定改变了结果」?
4. 有没有哪一刻你完全不知道该干什么?
5. 有没有哪个佣兵让你记住了名字?为什么?
6. 如果只能改一个地方,你会改什么?

### 4.3 过门判定

**阈值已由制作人写死(U25,2026-09-30),招募后不得回改**:

- **通过线**:至少**半数**试玩者自愿玩过首局;并且**陌生人组里至少 1 人**自愿继续(朋友组与陌生人组分开统计)。
- **不通过线**:超过半数人在问卷第 2 题**说不出招牌技能的使用时机和理由**,即判定战斗层没有立住,暂停批次 2。此条优先于通过线:留存达标但第 2 题不达标,仍按不通过处理。

下表的走向不变。

| 结果 | 判定依据(示例口径) | 走向 |
|---|---|---|
| **通过** | 多数人自愿玩超过首局;第 2 题能说出技能的时机和理由;第 3 题有具体事例 | 批次 2 按原规模做 |
| **部分通过** | 战斗有正面反馈,但第 4 题集中在同一个困惑点 | 先修困惑点(引导或 UI),再开批次 2 |
| **不通过** | 多数人没有自愿继续,或者第 2、3 题答不出来 | **暂停批次 2**,回到战斗层重新 grill,不往一个没被验证的战斗上堆装备深度 |

另外单独读第 5 题和说书人条目的反响。这是「故事密度」假说的第一份外部证据,直接决定阶段 B 里跨时间缝合的优先级。

## 9. 终局方向(U24)

### 9.1 制作人定调

- 类型是**反复刷的 RPG**,不走叙事驱动。
- 长期目标是**「最强公会」**,用**公会位阶阶梯**来度量,手感接近**怪物猎人的猎人等级(HR)**:晋升委托给方向,每升一阶解锁新内容。
- **设一个终局 Boss**,但**不要**「刷完了再爬天梯」的暗黑式后期。
- **「塔」只是一个玩法容器**,它在世界里的形态定为**裂隙 / 传送门**。
- **终局 Boss 就是裂隙之源**。击败它 = 故事终点。之后裂隙作为「余震」保持开放,游戏转入传承、收藏、宿敌的沙盒,**不设排名压力**。

### 9.2 公会位阶(轻量版 A14 进 G2,完整版在 G2 之后 grill)

- 位阶是**公会**的属性,不是佣兵的属性。佣兵会死,位阶不会掉。这正好和永久死亡形成张力:人换了一批又一批,公会的名号还在。
- 每阶有一道**晋升委托**(指定 Boss 首杀、指定裂隙深度、指定成就),完成后晋阶,并解锁版图、建筑、招募品质或裂隙深度。
- **轻量版 A14**:用现有的首杀和版图解锁,拼出前 3 阶(例:铁牌 → 铜牌 → 银牌),换掉 `goals.ts` 现在的平铺目标链。**不新增内容**,只改包装和晋阶演出。
- 完整版(阶数、终阶是否就是终局 Boss 的讨伐资格)在 G2 之后单独 grill。

### 9.3 对既有计划的影响

- **批次 3**:「高塔」在世界观和文案上改叫「裂隙」。玩法不变(赌局、段、规则词缀、怪物词缀)。代码里 `tower` 的命名**不强制重命名**,只改玩家可见的文案;如果要改代码命名,那是单独的工单。
- **怪物词缀与裂隙天然相接**:「从裂隙里爬出来的东西发生了变异」,这是词缀的世界观来源。闯入怪同理,是裂隙外溢出来的。
- **终局包**(终局 Boss + 位阶完整版 + 通关后沙盒的收束)放在阶段 D,**占位 6 人日**,等 G4 之后再细化。
- **未决**:终局 Boss 的机制与叙事;通关后沙盒具体有什么(宿敌、收藏、传承);位阶阶数。

### 9.4 位阶与终局结构(U25)

**5 阶**:铁牌 → 铜牌 → 银牌 → 金牌 → 传奇。

| 阶 | 晋升委托(方向) | 解锁 |
|---|---|---|
| 铁牌 → 铜牌 | 版图一 Boss 首杀 | 版图二 |
| 铜牌 → 银牌 | 版图二 Boss 首杀 | 裂隙(批次 3 的赌局玩法) |
| 银牌 → 金牌 | 裂隙达到指定深度 | 源头挑战资格 |
| 金牌 → 传奇 | **击败终局 Boss(裂隙之源)** | 故事终点;余震沙盒 |

- **终局 Boss 的门槛是两道叠加**(制作人「融合」方案):先到金牌,获得挑战资格;再在裂隙里下潜到指定深度,才能遇到源头。深度数值是结构占位(C4)。
- 轻量版 A14 只做前 2–3 阶,使用现有内容。
- **终局 Boss 的机制与叙事在 G4 之后单独 grill**,在那之前不锁任何设定。

**通关后的余震沙盒**(不设排名、不设天梯):

1. **宿敌讨伐**:杀过佣兵的词缀怪带着名字从余震里回来。这就是编年史联动的第 2 步(U22),在这里成为后期的核心动机。
2. **收藏与图鉴**:装备、怪物、词缀图鉴,以及传奇佣兵纪念册(批次 6 #6.1)。
3. **余震深度个人纪录**:只记录个人最佳,不做排行榜。

**退役 → 名人堂**(新增,代码里目前没有退役机制):

- 佣兵可以**主动退役**,进入纪念堂的名人堂,留下一项公会加成(例如:作为导师,新人获得少量经验加成)。这是比死亡更温和的退场方式,也解决了「几十小时后老兵永远不走」的问题。
- 死亡仍然是主要退场方式,退役不能替代永久死亡的分量:退役必须是**玩家主动选择**,不能成为规避死亡的万能按钮。例如:只能在公会内退役,远征中不可;或者需要满足资历门槛。具体约束在 G2 之后 grill。
- 排期:放在阶段 D 的终局包里(占位从 6 人日增为 8)。
