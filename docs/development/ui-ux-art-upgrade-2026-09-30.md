# A06：UI/UX 审计、美术资源与视觉升级方案

日期：2026-09-30。代码基线：`origin/main@426495a`，研究分支：`codex/ui-ux-art-audit`。**方案建议，未批准施工。**

## 1. 结论与范围

**返工状态（用户最新反馈）**：第一版“作战台/档案桌”框架与原版2D素材、世界观不吻合，用户明确否定；原“潮湿边境公会”总风格推荐撤回。布局和交互检查通过不能证明美术好看或被接受，下文审计事实继续有效，视觉建议已重写。

新的候选方向是**经典像素奇幻中的边境佣兵公会**：主画面由人物和冒险环境承担，铁木操作框、布旗、文书和纪念物来自这个世界的生活。保留英雄身份与冒险代价，也保留王国来信、酒馆和同伴故事里的温度。黑苔沼泽与龙脊山脉各有地景，不能把全世界做成绿色湿地。当前仅交付一张用原素材组成的战斗样稿，供判断方向；尚未获得视觉认可或批准施工。

下一次实际改造仍应先修能见度与接线问题，再把一段沼泽体验做完整。信息分组可以重排，但必须在真实素材、对应场景和屏幕尺寸中验证；不再沿用上一版平整绿色卡片作为出征/战斗的框架。委托、事件、回信及纪念保留文书属性。

用户本轮明确暂停原功能计划。U22 对齐和 #1.1 招牌技能暂缓施工，已经确认的产品结论仍有效。U23 说书人/战报卡尚未拍板，本报告不将其当成现有系统或已批准工作。不新增玩法、改战斗数值、采购、部署、推送或开 PR。

当前素材约束（用户 2026-09-30 补充）：**全免费，不做付费方案。** 这取代上轮“免费优先、少量付费补关键”的预算假设。逐个挑适合的怪物、场景物件、音效和效果，统一处理后采用；独有缺口以自绘/组合与现有引擎表现补齐。资源包提供原料，不决定游戏风格。

对比目标依据 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。2.34 是当前 token 的纯色配对计算，不是对所有截图像素做了全面合规审计；普通正文颜色目前约 9.18:1，问题集中在“淡提示承载重要信息”。

### 技术美术：三条已定位的调用链

1. **英雄分层未接通**：`src/ui/battle/pixelSprites.ts:513` 的 `URL_LAYERS` 是 `hero-guard/hero-priest/hero-ranger`，`spriteKeyFor()` 最后却返回 `guard/priest/ranger`；渲染器按返回 key 查分层，落到程序矩阵。文件虽已下载，展示链没有用上。当前 57 张 PNG 均为 32×32，28 怪物、19 分层/武器、10 地砖，共 167,464 字节。
2. **主题被重置**：App 在开始/恢复时设置主题；`BattleRenderer.setBattle()` 遇新战斗先 `clearUnits()`，后者调用无参 `drawBackdrop()`，默认使用暖砖。这能解释本轮沼泽截图；只补新背景 PNG 不解决问题。
3. **裁切与镜头共同作用**：`fit()` 为 cover 比例并设置居中偏移；ticker 的镜头震动随后写入 `root.x/y`，静止时又归零，丢掉这个偏移。修复要同时考虑容器比例、完整槽位、镜头基准和震动层；不是改一个 CSS 高度就完事。

这些是下轮修复候选，本轮没有修改它们。资源缺失时白块降级、远程命中声是否重复等旧报告线索，未在本轮重新复现，不列为已确认故障。

## 4. 视觉语言：内容应怎样被看见

### 推荐方向

**依据先于风格命名**：

| 已有设定/内容 | 证据入口 | 对视觉的约束 |
|---|---|---|
| “英雄会死，故事不会”，会长指挥、羁绊、成长与涌现 | [README](../../README.md)、[设计宪法定位](../DESIGN.md)；历史引擎迁移条款仍暂缓，不随本轮恢复 | 英雄应在场景和身份记录里出现；阵亡与遗物有分量。不能只把成员压成一串综合评分。 |
| 灰冠王国：军需、商路、教区、要塞；公会仍可决定为谁拔剑 | [王国来函与回信](../../src/data/kingdom.ts) | 铁器、旧木、布旗、印章与纸张有内容依据。并非皇宫管理界面，也不必全作阴森恐怖。 |
| 救人、逃兵、旧袍泽、诅咒、酒馆传闻；后果有代价也有温情 | [已实现的公会事件](../../src/data/guild-events.ts) | 生存压力与生活感并存；纸张/灯火可暖，危险的红色集中在预警和生命代价。 |

**环境**：以原32px像素素材的颗粒、透视和明暗建立场景。沼泽样稿先用已有湿苔地砖、石块道路、灰石哨站组成可站立的空间，再补少量灯火、布旗和水洼；这些是美术提案，不新增哨站剧情或地图节点。其他地区以后按矿道、旧战场、墓园与龙脊分别设计。环境需要更多同源地物，不能把反复铺地砖称为最终美术。

**公会与界面**：人物和环境是主画面，团长指令与成员状态收在一条连续的铁木底栏；框角、按钮切面、文字与精灵颗粒相近，避免现代大卡片和成片空白。布旗连接公会身份，纸面承载任务来由、取舍与纪念。蓝色旗帜在现有回信的蓝缎带意象中有依据，样稿“苔”字旗和蜡印只是提案，尚非正式纹章。

**材质分工**：暗铁承载操作、旧木承载公会工具、布旗承载身份、纸面承载叙事；旧铜用于少量扣件与选择，绿用于生命和实际地景，赭红用于危险。保留原素材文件，不用全局改色把不同画风勉强揉在一起；新取材先检查像素、轮廓、透视和题材，再做单件适配。

|---|---|---|

## 6. 技术落地与音频方向

### 不做过度设计的接入方式

- 维护一个很小的外观定义表，按职业/怪物稳定 ID 选图，字段只含来源帧、层、锚点、基础尺寸；源代码已有素材缓存就继续复用。名称关键词保留为旧内容兼容，不让本地化文案决定外观。
- 镜头区分适配基准与震动偏移；UI 血条、标签、集火点击区域保持可测试的投影。重排只改显示槽位，不改模拟站位、射程或命中规则。
- 地景是远景、战斗地面和少量前景，而不是完整可探索地图编辑器。首段样板需要一种地面、两三种识别物、阴影和一层氛围。
- 动效接真实 `BattleEvent`/机制状态，不能用图片动画自己决定伤害、冷却或“打断成功”。有移动/弹道的视觉到达要与已有命中处理核对，暂停/加速/恢复均不多播奖励或关键效果。
- UI 拆分以这次工作边界为限：出征摘要、角色详情、战斗指令/提示、统一浮层壳。逐项从大 App 提取，不先建页面路由框架/全局设计组件库/第二套游戏状态。
- 管理员实验室继续独立入口和存储。可复用同一渲染器做视觉样本，不让正式游戏出现测试关卡/调等级入口。

### 声音应服务游戏状态

当前 `src/ui/audio.ts` 已有 Master / Music / SFX 总线，以及命中、暴击、死亡、胜负、预告、打断、指令等声音。**不能报告成“没有战斗音效”。** 当前 BGM 是 112 BPM、32 步八分音符循环，约 **8.57 秒**，无场景切换；玩家只有全局静音。

建议小步升级：公会低密度主题、探索环境音/短主题、首领紧张主题三种状态；跨场景短淡入淡出，危险预告能压过环境音，普通命中避免密集叠加。第一轮只对同一段沼泽制作音画样板；自然播放十分钟后再判断疲劳、接缝和对提示的遮蔽。

保持现有关键危险声音作为兜底；不要为了真实武器音同时更换全部音效，也不引入复杂自适应配乐系统。候选音乐需要真人试听，决定氛围后才压缩/循环接入。

### 导入时最少要记什么

每个采用的文件登记：游戏用途、文件路径、作者、原发布页、下载版本/日期、授权及所需署名、是否修改、来源 SHA256。保存相关授权文本，项目鸣谢能从这份清单得到。

免费资源也可能限制原素材再分发，例如上表的 unTied 免费版与 NYKNCK。优先用 CC0/MIT 候选；如果采用其他许可，不把其 ZIP 或独立素材目录当作公共素材包发布，保留对应来源、署名与授权文本。这是候选的实际条款，不能只记“免费”便丢掉来源。

### 自动化与人工判断的分工

自动化检查：画布/标签/可点目标边界、页面无横向溢出、重要指令位置、浮层语义/焦点、已知 token 对比、缺图兜底、存档/战果同输入一致；对于表现改动也核对 UI→状态→模拟→奖励/保存调用链。

人工检查：先辨主操作，再看题材/剪影/材质，最后看动效/声音情绪；结合暂停态和播放态，不能只验漂亮截图。管理员测试模式可给可重放样本，真人试玩仍不可替代。

首段性能先记录现有帧耗时/显存/加载基线，再设目标（参考桌面 60fps、低端设备稳定 30fps）；本轮没有性能测量，不宣称当前达到该目标。预算可先要求环境/英雄样板新增图像压缩后不超过约 2MB、音乐仅加载使用的曲目；实际限额依设备和单文件构建代价校准。
