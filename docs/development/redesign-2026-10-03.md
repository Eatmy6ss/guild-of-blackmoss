## 1. 制作人的设计意图(本轮定调)

1. **每次选择是独立的,后果是相连的。** 走了水下,后面的路就会变难。玩家要能看见这条因果线。
2. **战争迷雾**存在的理由,是让玩家愿意反复下同一个副本。
3. **熟练度为选择而生。** 熟练度越高,看得越清楚,选得越准,负面后果越轻。但每一步仍然要自己选。
4. 叙事口吻是黑魂式的神秘感,带一点冷幽默(见 `story-templates.ts`)。
5. 外部试玩往后推,改成边做边由制作人自测,「实时修改」。

## 3. R1 副本层(工单粒度)

### R1.1 每趟随机的分层地图

**现状**:有 `routePlan`(固定步骤列表)、`junctionOptions`(岔口从关系表抽 4 个)、`applyNodeChoice`(只替换下一格)、`branches`(只改长度),以及每个副本 8 个固定 `routeNodes`。

**目标**:

- 新模块 `src/sim/dungeon-map.ts`,纯函数,不读 App 状态:

  ```ts
  export type TerrainId = 'water' | 'wild' | 'road' | 'camp' | 'under' | 'ruin' | 'grave' | 'sanctum' | 'lava'
  export type MapNodeKind = 'battle' | 'elite' | 'event' | 'rest' | 'treasure' | 'secret' | 'boss'
  export interface MapNode {
    id: string            // 'L2-1'
    layer: number         // 0 = 入口后第一层
    terrain: TerrainId
    kind: MapNodeKind
    encounterId?: string  // battle/elite/boss
    name: string          // 风味名,从副本的地形名表抽取(如 水域→「沉水洼地」)
    hidden?: boolean      // secret:只有高熟练度可见
  }
  export interface DungeonMap { seed: number; layers: MapNode[][]; edges: [string, string][] }
  export function generateMap(dungeon: DungeonDef, seed: number): DungeonMap
  ```

- **生成约束**:
  - 层数:3 人本 5 层,5 人本 6 层,另加最后一层 Boss。
  - 每层 2–3 个节点。每个节点至少有 1 条入边和 1 条出边,任意节点都能走到 Boss。
  - 全图至少 1 个 elite、1 个 rest,Boss 前一层至少 1 个非战斗节点。
  - 同一 seed 生成同一张图,使用现有 `createRng`,不用 `Math.random`。
- **Boss 层**:副本的全部 boss 遭遇按 `encounters` 顺序放进同一个 Boss 节点,依次连战。现有双 Boss 副本照旧。
- **副本数据**:
  - `DungeonDef` 新增 `terrains: Partial<Record<TerrainId, { weight: number; names: string[]; encounters: string[] }>>`,写明该副本有哪些地形、每种地形能出哪些遭遇、风味名有哪些。
  - 删除 `branches`、`routeNodes`、`routeRelations`。12 个副本各自 3–4 种地形,取值参考事件分池草案 §1。
- **玩家操作**:
  - 每战之后在地图上选一条出边。**没有「继续深入」按钮**,不选路就不能前进。
  - 「撤退回城」保留。
  - 出发前的岔路选择删除,它的职能由地图第一层承担。
- **挂机**:自动选路改为读地图。熟练度够时按已知信息选(血少选 rest/event,血多选 elite);不够时随机选。逻辑放在 `src/sim/` 里,不放 App。
- **存档**:`DungeonRun` 新增 `map: DungeonMap` 和 `nodeId`(当前所在节点)。删除 `steps`、`eliteAt`、`nodeIds`、`routeTaken`(遭遇序列由地图和已走路径推出)。
  - 存档升到 v23。读到旧格式的进行中远征时,按撤退处理:成员带着现有状态回城,不扣东西,通知一句「旧路线已失效,队伍已撤回」。兼容硬约束已解除,不做更多迁移。

**验收(新单测 `dungeon-map.test.ts`)**:

- 12 个副本 × 200 个 seed:可达性、层数、Boss 在最后、至少 1 个 elite 和 1 个 rest、同 seed 结果相同。
- 每个 `encounterId` 都存在于该副本的 `encounters` 中。

### R1.2 路况状态

走过的地形给队伍挂上状态,持续到本趟结束,并改变后面的战斗和地图。

- 新数据 `src/data/conditions.ts`:

  ```ts
  export interface RouteCondition {
    id: string; name: string; desc: string      // desc 写清实际效果,禁止只写氛围
    from: TerrainId[]                            // 哪些地形可能触发
    chance: number                               // 基础触发率
    battle?: { atk?: number; def?: number; hp?: number; heal?: number }  // 复用 RunBuffDef.mods 的四个乘区
    map?: { eliteWeight?: number; restHeal?: number; revealPenalty?: number; potionLoss?: number }
    clearedBy?: TerrainId[]                      // 走到哪种地形会解除(如 营地 烤干 湿透)
  }
  ```

- **首批 6 条**,数值是结构占位,受 C4 约束:
  - **湿透**:水域触发;受疗 ×0.9,泡坏 1 瓶治疗药;营地解除。
  - **惊动**:任何 elite 节点打完后触发;后续层 elite 权重 ×2。
  - **疲惫**:连走两个战斗节点后触发;rest 回复减半。
  - **迷途**:林野触发;下一层迷雾揭示降一级。
  - **暴露**:营地触发;下一场战斗敌方攻击 ×1.15。
  - **阴寒**:墓地触发;攻击 ×0.92;圣所解除。
- **触发**:走进节点时按 `chance × 熟练度修正` 掷一次,用 run 的 rng。同一状态不叠层,再次触发只刷新。
- **战斗修正**:和事件 `runBuff` 一样进 `startStep` 的乘区连乘(`run.ts:118-125`),不新开通道。
- **显示**:地图界面常驻显示当前状态条,写明效果和解除方式。节点悬停时显示「走这里可能:湿透」,是否显示取决于熟练度。

**验收(新单测)**:

- 走水域节点在固定 seed 下触发湿透,药水 −1,下一场受疗乘区为 0.9;走营地后解除。
- 惊动后,下一层生成的 elite 比例上升(200 seed 统计)。

### R1.3 熟练度:看穿迷雾,抵抗路况

| 熟练度 | 能看到的 | 路况 |
|---|---|---|
| 0–34 | 相邻一层节点的风味名和地形 | 基础触发率 |
| 35–59 | 相邻一层的节点类型;前两层的地形 | 基础触发率 |
| 60–79 | 前两层的类型;节点内容(敌人组成、事件类型);每条路可能触发的路况 | 触发率 ×0.75 |
| 80+ | 整张图的类型;secret 节点(暗道:跳过一层,或通往额外宝箱) | 触发率 ×0.5 |

- 删除「直捣 Boss」。它的职能由暗道接替:高熟练度看见捷径,但还是要自己选。这一点对应实施计划 #5.2,原先的终点是「消除变数、跳过内容」,和「反复刷」的方向相反。
- 熟练度获取不变:杂兵战 +1,Boss +2,按副本记。
- 新增入口:R4 的酒馆情报可以在出发前把指定副本的揭示等级临时提高一级。R1 只预留参数 `revealBonus`。

**验收**:

- `revealLevel` 的新单测覆盖四档。
- 地图 UI 在熟练度 0 时不泄露类型。用 e2e 断言节点 DOM 里不含「精英」「宝箱」字样。

## 5. R3 武器类型(结构粒度)

制作人的规则:**所有人都能用所有武器,但效果看职业、数值和特性**。例如战士可以拿法杖,但放不出法术,也不能用法杖远程攻击。

- `ItemBaseDef` 新增 `weaponType`,共 10 种:sword、axe、greatsword、dagger、bow、crossbow、staff、orb、tome、scepter。每种带 `mode: 'melee' | 'ranged' | 'spell'`。
- **站位和攻击方式由武器决定**:
  - melee 进前排,近战。
  - ranged 进后排,射击。
  - spell 进后排施法,**但只有施法职业(牧师、法师、术士)才能发挥**。其他职业拿 spell 武器时退化为前排近战钝击,武器只提供数值。
- **职业熟练**:每个职业有 2–3 种熟练武器类型。
  - 用熟练武器时,技能和招牌技完整可用。
  - 用非熟练武器时,标记了 `requires` 武器族的技能不可用(例如游侠的「瞄准射击」需要弓弩),普攻 ×0.85。
  - 熟练表放 `jobs.ts`,UI 在装备对比里明确提示「非熟练:失去 X 技能」。
- 例:游侠拿弓是后排射手(完整技能);游侠拿双匕是前排游斗,失去射击类技能,保留其余技能。是否给游侠一套匕首技能,在 R3 开工前 grill。
- R3 会改变战斗,所有胜率门禁都要重标。

## 6. R4 生平、委托、设施(结构粒度)

**生平(矮人要塞式)**

- 公会大事记只留里程碑:首杀、阵亡、升阶、委托结案、版图解锁、团灭重建。一趟 0–2 条。
- 其余写进**个人生平**:`Member.bio: { day, kind, text }[]`,每人保留最近 40 条加永久条目(加入、首次击杀 Boss、伤疤、心愿、羁绊里程碑、阵亡)。
- 人物页新增「生平」栏。说书人的故事同时写进当事人的生平。
- 名人堂读阵亡者的生平。

**王国委托**

- 每条委托给一样独特的东西,三类轮换:
  - 指定装备,带专属词条。
