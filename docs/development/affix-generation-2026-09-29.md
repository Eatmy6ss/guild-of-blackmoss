基准 `codex/enemy-scaling@63e29e3`；本轮 fetch 后 `origin/main` 仍为 `4816f3e`。保留已完成的 #0.2，只处理 #0.3/B04。用户同轮要求合理制定阶段验收、自动化检查并分析修正方向，允许根据开发证据校准文档，避免过度设计。

## 目标、规则与实际变化

普通词条原本按阶级区间随机抽样，再乘品质倍率；紫装追加词条却只取下限，T2 以上一律乘 1.5，并漏掉紫色 1.25。现在都调用 `rollAffixes(budget, pools, rng)` 内同一个取值函数，品质只提供预算，条数和去重共用。

- 保持既有 T1/T2/T3/T4 倍率 1/1.5/2.1/2.8、白/绿/紫倍率 0.9/1.08/1.25、品质概率及保底、追加 60% 机会、最多追加一条及基底条数上限。
- 保留普通词条先按阶级取整、再乘品质取整的顺序。品质判定 → 条数 → 普通词条 → 追加机会 → 追加词条的顺序保持。
- 追加词条开始对完整区间抽样，成功追加时新增一次 RNG 消耗。单件物品的普通词条和追加种类保持，但该种子后续掉落可能改变；不承诺跨版本重放旧掉落序列。
- T3 追加防御由固定 1.5 恢复到 2.63–10.5；固定 50% 区间抽样为 6.56。只有以后生成的装备使用修正预算，旧仓库、身上装备、遗物仍保留已存数值，不补发或重掷。
- 只在现有 `loot.ts` 收口：新增一个预算类型和一个内部抽取函数，没有通用掉落框架、加权池、配置系统或存档版本迁移。数据表、界面、评级、经济与事件均未改。

### 自动回归与证据

`src/sim/loot.test.ts` 七项用例随 `npm run verify` 自动运行，也可用 `npm test -- src/sim/loot.test.ts` 单独定位。内容为：B04 固定流、I4 跨词条与预算关系、追加容量/机会、所有基底数值边界和定义不可变、品质/保底与历史精度、真实杂兵/Boss 保底入口、旧装备迁移导入与新旧战斗投影。测试在 Node 内构造存档，未访问用户真实 localStorage。

兼容对照按 57 个真实基底 × 3 品质 × 30 个种子采集，排除随机物品 ID。修复前采集自 `63e29e3`，临时脚本/结果位于忽略目录 `.vite/affix-qa/`，不进入产品或提交；持久回归保留关系断言及代表性兼容样本。

测试中曾将紫装攻击样本手算为 4.78，实际为 4.77。重新运行 `63e29e3` 的真实生成入口确认白/绿/紫为 3.44/4.13/4.77 后校正了测试预期，没有为迁就断言改动生产舍入算法。这里的修正依据是原版实测，而不是把失败结果直接当作正确值。
