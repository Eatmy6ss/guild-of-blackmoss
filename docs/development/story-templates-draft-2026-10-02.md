# 说书人模板改写对照稿(Claude 起草,待制作人三审,2026-10-02)

依据 [DECISIONS.md](DECISIONS.md) U26:

- 前半句只写账本事实。收尾一句可以是氛围,但不能捏造事件、言行或场景。
- 不用代词(他/她/他们/他俩/TA),用名字或改写句式。
- 首杀陪葬分两组:同场阵亡,或者「没走到 Boss 面前」。
- 默契和创伤提高门槛,模板会用到新槽位 `stars` 和 `nth`。

**怎么审**:逐条看「改稿」一列。不同意的条目,在「三审」列写 ✗ 加意见,或者直接改字。

**和施工的关系**:第 5 组逻辑要用到新类型和新槽位,所以施工方会先把文末代码块原样放进 `src/data/story-templates.ts`,文件头标「三审中」。你审完后的改字是纯文本提交,不碰逻辑;文件头改为「定稿 + 日期」后才算过 G2 发包条件。

## 新增与变更的槽位

| 槽位 | 来源 | 说明 |
|---|---|---|
| `eventTitle` | `GUILD_EVENTS` 按 `due.refs.eventId` 查 `title`,去掉「第X幕·」前缀 | 找上门的那一幕的标题,例如「锈甲的来客」。替换原来的 `eventId`,原始 id 不再进入文本 |
| `stars` | bond-star 事实新增 `refs.stars` | 升到第几星 |
| `nth` | scar 事实新增 `refs.scarNth` | 本人身上第几条伤疤(含新增这条) |
| `killer` | 已有 | 首杀记在谁名下。注意:这是 `members.find(m => m.alive)`,即 Boss 战结束时第一名存活者,**不一定是出手的人**,之后的路上也可能阵亡(荆棘要塞的维克托在入口)。所以模板只写「首杀记在某人名下」 |

`itemUid` 不再被任何模板使用,可以从 `StorySlots` 里删掉。

## bond-star(默契升星;新门槛:首次升星或升到 3★)

门槛下只会出现 1★ 和 3★,所以模板不能写「又默契了一分」这种暗示「已经有过」的话。`★` 用 `'★'.repeat(stars)` 渲染。

| # | 原稿 | 改稿 | 改动理由 | 三审 |
|---|---|---|---|---|
| 1 | ${a}和${b}又默契了一分。战场上,一个眼神就够了。 | ${a}和${b}的默契升到了${★}。并肩活着回来的次数,账本都记着。 | 「又」;1★ 时「一个眼神就够了」夸大 | |
| 2 | 多少场仗一起活下来,才换得来这种默契——${a}和${b}之间,话越来越少了。 | 多少场仗一起活下来,才换得来这${★}——${a}和${b}之间的话,可以少说几句了。 | 「话越来越少」是捏造的变化 | |
| 3 | ${a}和${b}的配合已经不需要口令。敌人最先发现的,往往是这个。 | ${a}和${b}的配合到了${★}。敌人最先发现的,往往是这个。 | 「不需要口令」在 1★ 时夸大 | |
| 4 | 酒馆里常见他俩拼桌。战场上的默契,都是这么喝出来的——至少${a}是这么说的。 | ${a}和${b}一起从远征里活着回来了。默契:${★}。 | 「拼桌」「这么说」都是捏造;「他俩」 | |
| 5 | ${a}替${b}挡过一下,${b}替${a}挡过更多下。账算不清了,索性不算了。 | ${a}和${b}的默契到了${★}。谁欠谁更多,账已经算不清了,索性不算。 | 「挡过」是捏造的事件(U26 点名) | |
| 6 | 默契这东西看不见摸不着。但${a}和${b}并肩站着的时候,前排的活好干多了。 | 默契这东西看不见摸不着,但名册上写着:${a}和${b},${★}。 | 「前排」预设了两人的职责 | |
