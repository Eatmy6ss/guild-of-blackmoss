# #0.2 统一敌人缩放入口

基准 `origin/main@4816f3e`，分支 `codex/enemy-scaling`。PR #3 已合并，制作人侧最新记录确认 M1 通过；本轮按已发布工单只完成 #0.2/B03。

## 修复与行为边界

之前初始敌人在 `createBattle` 中吃地图与场次倍率，增援直接从原始定义创建。现统一在 `difficulty.scaleEnemy()` 做生成时的 HP/攻击乘算；初始怪、Boss、增援与高塔都调用此入口。

- `DifficultyInput` 暂保留现有地图字段并携带 `modifiers`：精英标记、猎杀倍率、塔层。本项不提前实施 #0.8 的 rating/archetype 模型。
- `createBattle` 第九参数由裸数值改为 `DifficultyModifiers`。远征明确传入精英与首场猎杀；初始小怪与增援同时带精英标记，供已有精英伤害判定读取。调用点与两处历史测试已迁移。
- Boss 保留本场地图/修饰的独立快照，召唤时取用。外部配置变化及下一场开始不会改变当前增援；猎杀仅首场生效。
- 高塔 `towerFloorScale()` 委托统一入口，产出的定义带 `difficultyScaled` 标记。进入战斗与实际召唤时不再乘一次，且不混入其原副本的地图倍率。
- 普通敌人攻击单次取整、Boss 攻击两次取整的既有差异均保留；HP、防御、速度、技能与数据表不作曲线调整。战中狂暴、强化等机制仍属于状态变化，不是生成时难度缩放。
- 源定义未被改写；标记只出现在派生定义。没有修改正式存档结构、结算、奖励、事件表、管理员入口或 DESIGN。

**预期的实际变化**：副本增援回到同图同类初始怪的强度。以普通烬石隘口为例，狂徒增援从 520 血/19 攻变为 1064 血/38 攻，唱诗者从 440 血/12 攻变为 900 血/24 攻。这是补齐既有倍率；Boss 初始攻血和原高塔数值保持。本修复会增加过去漏算的增援压力，不等于全图难度已验收。

## 验证

- 修复前新增真实召唤回归复现失败：黑苔同定义初始怪 293 血、增援 266 血，证明缺口并非仅存在于隘口。
- `src/sim/difficulty.test.ts` 五项关系/调用链回归通过：全图有召唤 Boss 的初始/增援一致性（普通、精英、猎杀、叠加四组）；远征首场修饰与后场清除；难度快照隔离；九个塔层的初始与增援单次缩放；数据表不变、标记可序列化和重复入口不放大。
- 从修改前实际引擎采集 56 个现有遭遇 × 4 组场次修饰，共 224 组初始敌人数值；改后逐项一致。另采集 8 个塔层及其增援池，改后逐项一致。临时采集工具位于忽略目录 `.vite/scaling-qa/`，不作为产品或提交内容。
- 完整 `npm run verify` 退出 0：Vitest 13（新增 5 + 原 8）、管理员类型检查、smoke 47、历史玩法与王国回归、游戏类型检查和生产构建通过。`git diff --check` 通过。
- 本轮未新增 UI，未重做浏览器人工通关；验证使用实际模拟入口与召唤分发器，不直接伪造生成结果。没有对全职业胜率、自然装备难度或增援阶段操作感作通过结论。
